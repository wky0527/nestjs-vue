# 招聘自动化工具 —— 面试讲述手册（招聘业务视角）

> 适用岗位：招聘专员 / TA（人才招募）/ HRBP（招聘方向）
> 核心原则：**全程用招聘语言讲，技术只是"我怎么把方法落地"的工具**。
> 面试官要听到的不是"会写代码"，而是：**你会对齐岗位画像、会做人才地图、会定触达策略、会用数据复盘招聘动作。**

---

## 一、一句话定位（开场就定调）

**「我做的是一个研发岗位招聘运营工作台：把『岗位画像 → 目标企业人才地图 → 人才搜寻与触达 → 初筛与面试推进 → 数据复盘』做成一条闭环，用数据代替感觉来判断渠道值不值得投、画像有没有跑偏、候选人卡在哪个环节。」**

紧接着补一句（把技术藏到业务后面）：
> 我自己把这个流程做成了工具，这样画像、台账、漏斗、渠道效果都能实时看到，不用每周手动扒 Excel。

## 二、电梯稿（背三档）

### 30 秒版

> 我平时在做技术岗招聘，最头疼的是三件事：岗位画像跟用人部门对不齐、渠道预算不知道往哪投、候选人跟到后面就乱了。所以我按自己的招聘习惯搭了一个工作台：先把 Web 前端工程师的**人才画像**拆成技术栈、年限、项目经历、业务背景、薪资期望五个维度；再按这个画像梳理**目标企业**，分 S/A/B/C 梯队，标出每家的人才分布特点和搜索方向；然后是**人才 Mapping 台账**，把搜到的人按"已搜索→有效简历→初步沟通→有意向→面试邀约"逐级流转，每一步留痕；最后用**漏斗和渠道数据**反过来校验我的画像和搜索策略对不对。相当于把我这套招聘动作标准化、可复现了。

### 2 分钟版（加数据与结论）

在 30 秒版后补三点：

1. **口径**：漏斗我按"到达率"统计——进入某环节的累计人数，而不是当前停在该环节的人数，不然已经推进到二面的人就不算进一面，转化率是假的。
2. **实测结论**：目前人才池 42 人，搜索→有效简历 65.7%，有效简历→初步沟通 65.2%，沟通→有意向 60%，有意向→面试邀约 55.6%，整体邀约转化 11.9%；渠道上**内推 5 人出 2 个邀约（40%）、领英 22%，GitHub 8 人 0 邀约**——所以 GitHub 我打算只做人才储备、不投主动触达时间。
3. **节奏管理**：候选人到期/逾期跟进会自动提醒，跟进动作全部记日志，交接或复盘时能看到一个人是怎么推进的。

### 5 分钟版
按第四节逐模块讲，每模块 45~60 秒，讲完停一下等追问。

## 四、六个模块的业务讲法（核心内容，逐个练）

### 模块 1：人才画像梳理 —— 关键词「对齐用人部门」

**业务话术**
> 画像不是 JD 的复制。JD 是给候选人看的，画像是给我自己搜索和判断用的，必须能拆成"硬性条件 + 可谈条件"。

我拆的五个维度（Web 前端为例）：

| 维度 | 我具体定成什么 | 为什么这样定（业务价值） |
|---|---|---|
| 技术栈 | Vue3 / React / TS / Vite / Node / 小程序 | 直接决定搜索关键词命中率；一家公司的技术栈也决定去哪找 |
| 工作年限 | **3-7 年**为主区间 | <3 年撑不住独立负责模块，>8 年薪资超出预算且岗位预期不匹配 |
| 项目经历 | 必备：独立完成需求到上线；加分：性能优化、组件库/脚手架、跨端、开源 | 区分"会用框架"和"能解决问题"，加分项是溢价谈判的依据 |
| 业务背景 | 电商 / 社交 / 音视频 / SaaS / 金融 / 出海 | 业务复杂度迁移成本比技术栈更低，同行业候选人上手快 |
| 薪资期望 | 20k-35k·15 薪 | 提前锁定可谈区间，避免聊到最后一步卡在薪资 |

再补两个我认为是画像"合格标准"的东西：
- **输出可直接执行的检索式**：画像最后必须落到 `Vue3 + TypeScript + 3-7年 + 电商` 这种平台能用的关键词组合，否则画像是空的。
- **和用人部门确认"不可让步项"**：我会明确标出哪几条是硬性（低于 3 年不看、学历大专以下需项目突出），避免初筛标准和业务面试官不一致，出现"HR 推的人被一句『不合适』打回"。

### 模块 2：目标企业人才地图 —— 关键词「供给策略」

**业务话术**
> Mapping 和"搜简历"最大的区别：搜简历是找现在能投的人，Mapping 是**经营一家公司未来 6-12 个月的人才供给**。

梯队怎么分（不是简单按公司名气）：
- **S 梯队**（字节、腾讯、阿里）：画像匹配度最高，但薪资溢价明显、被抢手 → 打法是**长期储备 + 精准触达**，不追求快回复；同时盯组织架构调整窗口，这是流出人才最集中的时候。
- **A 梯队**（美团、快手、小红书、拼多多）：人才池稳定、供给量大 → **主力搜索范围**，性价比和响应率都不错。
- **B 梯队**（大疆、招行卡中心、好未来、Shopee、SHEIN）：单一维度契合（可视化 / 小程序 / 出海 / 教育流出） → 当作**差异化补充**，尤其是行业调整期流出的成熟人才，稳定性好、薪资在区间内。
- **C 梯队**（PingCAP、涂鸦智能）：人才池小、触达成本高 → **只做观察和储备**，不投入主动时间。

每家企业我强制自己填三栏，否则这条地图没意义：
1. **人才分布特点**：团队规模、平均司龄、流动率（司龄短 → 更愿意看机会；司龄长 → 需要更强的理由才动）
2. **搜索方向**：具体到业务线 + 职级 + 年限（"看抖音/电商线 3-6 年 P6-P7"，而不是"看字节的人"）
3. **薪资水平**：用来判断我方 offer 有没有竞争力，也用来提前设计期望管理话术

### 模块 3：人才 Mapping 台账 —— 关键词「可交接、可复盘」

**业务话术**
> 台账解决的是"人跟丢了"和"不知道卡在哪儿"。我定的字段不是随手记，是按**能不能支撑复盘**来设计的。

| 字段 | 业务用途 |
|---|---|
| 技能关键词 | 和画像比对，标匹配度 high/mid/low，决定优先级 |
| 企业背景 + 职级 | 判断跳槽动机合理性、薪资基线 |
| 来源渠道 | 后续算渠道产出的唯一依据（**必须当场记录，事后补全必失真**） |
| 当前薪资 / 期望薪资 | 提前判断可谈性，别等面试完才发现差 30% |
| 跟进状态 | 见下面状态机 |
| 备注 | 只记事实（"电话沟通，意向较强，约面试"），不记主观评价 |

状态机（我认为这是台账最有价值的部分）：

```
已搜索到 → 有效简历 → 初步沟通 → 有意向 → 面试邀约
                    ↘ 未回复（回到触达节奏）
                    ↘ 不匹配（进人才池储备，标注原因）
```

三个业务规则我自己定死：
- **"有效简历"的门槛要写清楚**：不是简历收进来就算，必须满足硬性条件——不然有效简历率虚高，后面每一环转化率都被稀释。
- **未回复不等于失败**：我标 `未回复` 而不是直接删，按"3 天换渠道再触达一次、一个月后归入人才池"的节奏处理。技术候选人普遍"在职看机会"，沉默常常是时机问题不是意愿问题。
- **不匹配要标原因**（薪资超预算/技术栈不符/年限不足/背景不相关），因为这批人是下次同类岗位的现成储备，也是修正画像的证据。

### 模块 4：跟进提醒与沟通节奏 —— 关键词「SLA」

**业务话术**
> 招聘是时序生意，触达慢一步人就接了别家的面试。我给自己定了节奏标准：

- 首次触达：搜索到当天完成（技术候选人活跃期短）
- 无回复：3 天后换一个渠道/换一版话术再触达，最多两轮
- 沟通后：约定时间内必须回访，到期未处理系统提示逾期天数
- 面试后：24 小时内给反馈，无论通过与否——**候选人体验是我长期供给的来源**

跟进日志的价值我会举一个场景：**同事请假、岗位交接，或者半年后候选人重新看机会时，能立刻接上之前聊到哪、他关心什么（薪资/技术方向/通勤/团队规模）**，不用重新问一遍。

### 模块 5：简历初筛与 AI 辅助 —— 关键词「一致性 + 人做决策」

**业务话术**
> 初筛最大的风险不是慢，是**不一致**：同一个人在不同状态下的判断标准会漂移，也会因个人偏好误杀。我用 AI 做的是"按固定标准先过一遍"，人做最终判断。

- AI 检查的三件事：经验年限、学历、技术栈与岗位要求的匹配缺口，输出优势、风险、以及**针对性的面试建议**（比如缺性能优化经验就建议面试官追问具体案例）。
- **我特意不给它自动拒绝的权限**：结论只到"待人工确认"，我可以采纳、改分后采纳、或明确否决并留原因。**AI 判断错一个人，我失去的是一个候选人；人判断不一致，我失去的是整个流程的可信度。**
- 对用人部门输出时，"建议面试题"很有用——业务面试官最怕候选人简历看不懂，我把疑点直接列出来，面试质量更稳。

> 如果面试官问"这不就是自动筛简历吗"，答案就是上面这段：**AI 做一致性校验，人做决策，且全程可追溯。**

### 模块 6：漏斗与渠道数据 —— 关键词「定位问题该改哪个动作」

**先讲口径（最能体现专业度）**
> 我用的是"到达率"：进入某环节的累计人数（处于该环节及之后环节的人数之和），不是当前停在该环节的人数。按后者算，已经推进到二面的人就不算进一面，转化率会失真甚至出现漏斗变宽的反常结果。

**各环节转化率说明什么、我该改什么（背这张表）**

| 环节 | 我的实测 | 若偏低，说明什么 | 我的动作 |
|---|---|---|---|
| 搜索→有效简历 | 65.7% | 关键词跑偏 / 目标企业选错 / 渠道供给质量差 | 改检索式、调梯队、换渠道 |
| 有效简历→初步沟通 | 65.2% | 触达话术不够吸引、触达时间不对、职位吸引力不足 | 重写首触话术（讲技术栈+业务+成长），改到工作日晚间/周末触达 |
| 沟通→有意向 | 60% | 薪资期望超预算、职级不匹配、公司背书弱 | 前置薪资区间筛选，用可谈空间换期望，或上移岗位定位 |
| 有意向→面试邀约 | 55.6% | 流程排期慢、面试时间不灵活、面试官档期 | 缩短安排周期，提供晚间面试选项 |
| 整体搜索→邀约 | 11.9% | 综合效率 | 看最大流失环节优先修，不平均用力 |

**渠道结论（讲一个"我做了决定"的例子）**
> 内推 5 人出 2 个邀约（40%），领英 22%，GitHub 8 人 0 邀约。所以我不是关掉 GitHub——那上面的人质量并不差，只是**不适合主动触达**，我改成纯储备：先收藏、有内容互动再私聊。这就是数据改变动作，不是数据改变预算。

> 注意：这里的百分比来自我自己的模拟台账，用来说明分析方法；真实业务里我会用当月实际投递数据算，并且参考行业常见区间做基准对比（不同口径/不同岗位差异很大，我不会把经验值当标准答案）。

## 五、指标体系（面试官问"你关注哪些数据"时用）

```
供给指标：搜索人数、有效简历率、简历来源结构（渠道/企业梯队）、人才池储备量与激活率
转化指标：到达率漏斗、各环节转化率、整体搜索→邀约转化率、offer 达成率
效率指标：单岗招聘周期（首触到入职）、各环节处理时长（响应速度）、逾期跟进数量
质量指标：过筛后到面率、面试通过率、候选人体验（拒绝是否给反馈）
成本指标：渠道单人成本、猎头 vs 自主交付比 ← 我这套台账已具备算它的数据基础，下一步就做
```

主动说一句"**目前没做成本维度**，但渠道、时间、状态都在了，加上单价就能算出单人招聘成本"——既诚实又显示你知道 TA 的终极指标是成本和质量。

## 六、现场演示路线（招聘岗版，3 分钟）

打开系统，**按招聘动作顺序讲，不要按菜单顺序讲**：

| 步骤 | 页面 | 业务解说词 |
|---|---|---|
| 1 | 人才画像 | "这是我对 Web 前端这个岗位的画像，五个维度。技术栈这块我会直接转成招聘平台的检索式；必备项和加分项分开，是因为加分项决定我能不能谈下高于预算的候选人。" |
| 2 | 目标企业 | "按画像我分了 S/A/B/C 梯队。看这家——司龄短、流动率高，所以适合快投快聊；这家金融公司司龄 5 年以上，求稳，那我就要用稳定性、成长空间这类理由去打动。" |
| 3 | Mapping 台账 | "所有搜到的人进这张表，来源渠道当场记录，不然渠道分析没法做。状态我直接在这里流转，流转会留时间线。" 现场把一个人从"已搜索"推到"初步沟通"，点开"轨迹"。 |
| 4 | 候选人管理 | "跟进提醒在这里，逾期的会顶到最上面，我每天上班先看这条。" |
| 5 | AI 简历分析 | "简历先按固定标准过一遍，它给评分和缺口。注意这一步**它不能替我决定**，我要点采纳/修改/不采纳，理由会记下来。" |
| 6 | 数据分析 | "最后看结果：漏斗哪一环流失最大决定我下一步改什么，渠道这张表告诉我时间该往哪投。" |

## 七、高频追问 & 业务向答案

**Q1：Mapping 和常规搜简历有什么区别？**
> 搜简历是"这个岗位缺人→我去找人"，交付完就结束；Mapping 是"这个岗位未来一年会持续缺人→我把这几家公司的人才结构和人本身经营起来"。产出差别是：前者只有当下交付，后者有**人才池**，下次开同类岗位时首月邀约量能明显起来，还能省下猎头费。

**Q2：你怎么衡量 Mapping 做得好不好？**
> 三个指标：**人才池储备量**（同类岗位未开放前手上有多少可触达的人）、**池内激活率**（这些人在真实岗位上完成沟通/面试的比例）、**同类岗位交付提速**（从 JD 到首个面试邀约的天数）。如果只看当下投递量，Mapping 的价值永远体现不出来，因为它收益是滞后的。

**Q3：漏斗显示初筛通过率很低，你怎么办？**
> 先分清是"筛得严"还是"找得错"。我会拆三个可能：① 关键词或检索式跑偏（搜来的人技术栈根本不对）→ 改搜索；② 目标企业选错（供给结构和岗位需求不匹配）→ 调梯队；③ 画像定得过高（薪资/年限要求超出市场）→ 带着数据回去跟用人部门重新谈画像，比如"3-7 年 + 20-35k 这个组合在 S 梯队拿不到，要么放宽年限、要么上调预算、要么接受 B 梯队为主"。**用数据谈需求比凭感觉谈有效得多。**

**Q4：某渠道投递量大但面试转化低，你怎么处理？**
> 我不会直接砍掉。先看是质量还是效率问题：如果这批人过不了用人部门那关，说明渠道供给和画像错位，我要么换在该渠道的检索条件，要么降低它的优先级、把主动触达时间挪走；如果是候选人接了邀约不来，那是我的流程和沟通节奏问题（安排太慢、反馈不及时），跟渠道无关。砍预算只在"成本"维度算得过来时才做。

**Q5：候选人不回消息怎么办？**
> 分三种：① 触达内容问题——首条消息有没有讲清"技术栈 + 业务方向 + 成长/团队亮点"，只发"我们有个前端岗位聊聊？"回复率一定低；② 时机问题——在职看机会的人白天不方便，改到晚间/周末；③ 意愿确实低——那就转人才池，标注原因，季度性回访。我坚持一件事：**沉默不等于拒绝**，删掉人就等于永久丢掉这个线索。

**Q6：薪资期望超出预算你怎么谈？**
> 先摸清结构（总包、现金/股票比例、几薪、奖金），再谈"我们这边可谈的空间在哪"——薪资涨幅不够时用职级、技术话语权、业务前景、工作地点/通勤这类非现金点补。同时给用人部门反馈市场实况：**"这个薪资段本周聊了 8 个人，只有 1 个能接受，且年限要放宽到 3 年以内"**，这是最有力的预算沟通材料。

**Q7：AI 筛简历会不会有歧视/误判风险？**
> 会，这是我特意限制它权限的原因。第一，AI 只做**标准一致性检查**（经验、学历、技术缺口），不做淘汰决定；第二，学历、年限这类条件我只作为参考分，硬性卡什么由我和用人部门事先约定并写在画像里，不由模型临时判断；第三，所有结论要人工确认且留痕，出现误筛能回溯定位是哪条标准出的问题。候选人如果申诉，我要能解释"为什么被拒"。

**Q8：候选人信息安全怎么保障？**
> 最小必要原则：只收集岗位评估必需的信息，手机号这类敏感字段应当脱敏存储、按权限查看；台账不外发、不截图给业务方（我导出 CSV 只用于自己复盘）；未录用的候选人数据按内部留存期限处理。我这套工具是个人单用户版，如果给团队协作，第一步就是加账号权限和访问日志——这是我明确知道要补的。

**Q9：如果不用工具，只用 Excel，你这套方法还成立吗？**
> 成立，工具只是让口径不漂移、统计不手搓。我会先建三张表：画像表、目标企业表、人才台账表，状态列做成固定下拉（不然每个人写法不同没法统计），渠道列必填。手工版我完全可以跑，只是漏斗和渠道产出要每周花半天算，而且容易算错——我做工具是为了**省出时间去做沟通和谈判**，不是为了炫技术。

**Q10：你怎么和用人部门/业务面试官配合？**
> 三个动作：① 岗开前用画像对齐，把"不可让步项"和"可谈项"确认下来并记录；② 每周给一份简报：搜索/有效/沟通/邀约人数、卡点在哪、市场薪资实况，让业务能理解为什么慢；③ 收集面试反馈，把被面试官打回的原因反哺到画像（比如"过不了二面的人普遍缺大规模并发经验"→把这条从加分项提到必备项）。

## 八、讲述原则（招聘岗版）

1. **动作 → 指标 → 决定**：每段都以"我做了什么、看到什么数、所以下一步怎么调"收尾。
2. **别报技术名词**：Vue/Express/SQLite 一句带过（"我自己搭了个小工具"），面试官若感兴趣会追问，那时再展开。
3. **多讲"我定死的规则"**：有效简历的门槛、来源渠道必须当场记、沉默不等于拒绝、AI 不能自动淘汰——**这些标准才体现你是专业招聘，而不是投简历的执行者**。
4. **敢说边界**：数据是模拟的、成本维度还没做、工具没权限体系。诚实说明 + 给出下一步方案，比包装更可信。
5. **落回岗位价值**：结尾一定回到"我关心的是更快拿到合格候选人、降低对猎头依赖、让流程可复盘"。

## 九、反问面试官（体现 TA 专业度）

- "团队目前用什么 ATS/招聘系统？各环节指标的统计口径是统一的吗？"
- "技术岗招聘里，猎头、自主搜寻、内推的预算占比大概多少？渠道投入是谁决定？"
- "用人部门对画像的配合度如何，通常在哪一步容易卡——是简历质量还是面试排期？"
- "如果我进来，前 3 个月最希望我解决的是到岗速度，还是渠道结构优化？"

> 这四个问题分别对应：数据基础、成本决策权、协作效率、入职目标。**问最后那个，能直接把面试推向"你来了会怎么干"的讨论。**
